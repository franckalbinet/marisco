Convert the Fram Strait I-129, U-236 and U-238 seawater records on Zenodo to MARIS NetCDF4

This handler converts the Fram Strait seawater records on Zenodo to MARIS NetCDF4. RECORDS lists six records, from cruises between 2020 and 2025. They hold I-129, U-236 and U-238 measurements from two laboratories: the Laboratory of Ion Beam Physics at ETH Zürich (ETH) and the Vienna Environmental Research Accelerator at the University of Vienna (VERA). Laboratory reconciliation is in progress. The pipeline:

  • aligns the columns of each record to one schema, and keeps one laboratory’s measurement for each sample and nuclide
  • renames columns to MARIS names, parses dates and computes depth from pressure
  • reshapes the value and uncertainty columns into one row per measurement
  • converts U-238 from ppb to atoms per kg
  • maps nuclides, units and laboratories to MARIS ids, and marks every value as detected.

encode then adds global attributes and writes the SEAWATER group to one NetCDF file.

from marisco.nc2csv import to_csv
from marisco.configs import get_lut, NC_VARS

Curation summary

Each row is a decision MARIS made about the provider’s data. The last column is the change in the provider’s delivery that would make the decision unnecessary. The linked section has the details. What the pipeline drops lists each column, value and sample that the output leaves out.

Load data

Each Zenodo record has its own adapter. An adapter takes a downloaded record and returns its columns as RAW_COLS lists them, in that order. load_data then combines the records.

Align record schemas

The FS2020_21 record holds measurements from ETH and VERA. The FS2022 to FS2025 records hold ETH measurements only. FS2020_21 names some metadata columns differently from the other records, and FS2022S names its coordinates Latitude and Longitude.

Each measurement column has a twin with its uncertainty, such as I129_at_l and unc_I129_at_l. Some column names start with the laboratory and some don’t. In FS2020_21, the unprefixed columns hold ETH’s I-129 and VERA’s U-236 and U-238. The FS2022 to FS2025 columns have no prefix and are all ETH’s. _prefix_lab_cols adds the missing prefix to a measurement column and its uncertainty twin:

Exported source 
def _prefix_lab_cols(df: pd.DataFrame, lab: str, cols: list) -> pd.DataFrame:
    "Prefix `cols` and their `unc_` twins with `lab_`, recording which lab produced them"
    ren = {c: f'{lab}_{c}' for c in cols} | {f'unc_{c}': f'{lab}_unc_{c}' for c in cols}
    return df.rename(columns=ren)
df = pd.DataFrame(dict(Station=[47], I129_at_l=[1.7e9], unc_I129_at_l=[1.4e8]))

Laboratory precedence

MARIS reports one laboratory’s measurement for each sample and nuclide. The data provider set this precedence. ETH measured I-129 in every case. For U-236 and U-238, the handler uses VERA’s value when VERA reported one, and ETH’s value otherwise. _prefer_vera clears ETH’s value and uncertainty wherever VERA reported a value:

Exported source 
def _lab_meas(lab: str, stem: str) -> tuple:
    "Value and uncertainty column names for `stem` as measured by `lab`"
    return f'{lab}_{stem}', f'{lab}_unc_{stem}'
Exported source 
def _prefer_vera(df: pd.DataFrame, stem: str) -> pd.DataFrame:
    "Where VERA reported `stem`, clear ETH's measurement (value and unc)"
    (v, vu), (e, eu) = _lab_meas('VERA', stem), _lab_meas('ETH', stem)
    df.loc[df[v].notna(), [e, eu]] = np.nan
    return df

VERA reported U-236 for the first sample only. ETH’s value is cleared for that sample and kept for the second:

Record adapters

_RENAMES maps the metadata column names that differ between records to their RAW_COLS names. _normalize_2020_21 and _normalize_2022_25 apply it and the steps above to their records. _normalize_2020_21 also drops the ETH U-236/U-238 ratio columns, and converts dates from dd/mm/yyyy to yyyy-mm-dd. _normalize_2022_25 builds Date from Year, Month and Day when a record has no Date column.

Exported source 
_RENAMES = dict(Bottle='Niskin', Salinity_ctd='PracticalSalinity', Temperature_degC_ctd='Temperature_degC',
    Latitude='Latitude_degN', Longitude='Longitude_degE')
Exported source 
def _normalize_2020_21(df: pd.DataFrame) -> pd.DataFrame:
    "Align FS20/FS21 records (ETH + VERA labs) to the canonical Fram Strait raw schema"
    df = df.drop(columns=[c for c in df.columns if 'U236_U238' in c])
    df = df.rename(columns=_RENAMES)
    df = _prefix_lab_cols(df, 'ETH',  ['I129_at_l', 'I129_at_kg'])
    df = _prefix_lab_cols(df, 'VERA', ['U236_at_l', 'U236_at_kg', 'U238_ppb'])
    for stem in ['U236_at_l', 'U236_at_kg', 'U238_ppb']: df = _prefer_vera(df, stem)
    df['Date'] = pd.to_datetime(df['Date'], format='%d/%m/%Y').dt.strftime('%Y-%m-%d')
    return df[RAW_COLS]
Exported source 
def _normalize_2022_25(df: pd.DataFrame) -> pd.DataFrame:
    "Align FS22-25 records (ETH lab only) to the canonical Fram Strait raw schema"
    df = df.rename(columns=_RENAMES)
    if 'Date' not in df.columns: df['Date'] = pd.to_datetime(df[['Year', 'Month', 'Day']]).dt.strftime('%Y-%m-%d')
    df = _prefix_lab_cols(df, 'ETH', ['I129_at_l', 'I129_at_kg'])
    return df.reindex(columns=RAW_COLS)

Compute depth from pressure

The FS2022 to FS2025 records report pressure, not depth. AddDepthCB computes the sampling depth in metres from Pressure_dbar with gsw.z_from_p, for every record. The gsw package implements the Thermodynamic Equation of Seawater 2010 (TEOS-10). The reported latitude sets the gravity correction. Depths are rounded to one decimal place. FS2020_21 also reports Depth_m, and its values agree with the computed depths to within 0.05 m:

Reshape to one row per measurement

Each raw row holds one sample. Each of its measurements sits in its own column, named for the laboratory, nuclide and unit, with a twin column for the uncertainty. MARIS stores one measurement per row, with the laboratory, nuclide, unit, value and uncertainty in separate columns.

ImportantFEEDBACK TO DATA PROVIDER

Column headers in the Fram Strait dataset encode multiple pieces of information (lab, nuclide, unit) into a single string. This adds friction to data ingestion, since every new dataset with a different naming convention requires custom parsing logic. MARIS prefers a tidy data layout (Wickham 2014, doi:10.18637/jss.v059.i10), where each column holds a single variable, and metadata like nuclide, unit, and method are stored as separate columns, not baked into the header.

MEAS_PAT splits a measurement column name into the laboratory, the uncertainty marker, the nuclide and the unit:

Exported source 
MEAS_PAT = re.compile(r'^(?P<LAB>[A-Z]+)_(?:(?P<UNC>unc)_)?(?P<NUCLIDE>[A-Za-z]+\d+)_(?P<UNIT>.+)$')

ETH_unc_I129_at_l is ETH’s uncertainty for I-129 in atoms per litre. A value column has no unc part:

test_eq(MEAS_PAT.fullmatch('ETH_unc_I129_at_l').groupdict(), dict(LAB='ETH', UNC='unc', NUCLIDE='I129', UNIT='at_l'))
MEAS_PAT.fullmatch('VERA_U238_ppb').groupdict()
{'LAB': 'VERA', 'UNC': None, 'NUCLIDE': 'U238', 'UNIT': 'ppb'}

ImportantFEEDBACK TO DATA PROVIDER

ETH’s I-129 and VERA’s U-236 are reported both in atoms per litre (at_l) and in atoms per kg (at_kg). Each at_kg value equals the at_l value divided by a seawater density between 1020 and 1029 kg/m³. For U-236 in FS2020_21, this is the record’s density_kg_m3 column. MARIS keeps both units for now: 517 measurements appear twice in the output, once in each unit. FS2022, FS2023, FS2024 and FS2025 report I-129 in at_l only.

Should MARIS keep both units, or only the unit you measured? If only one, which unit is it?

Each value has an uncertainty. The output therefore has half as many rows as there are non-empty measurement cells in the raw data:

meas = [c for c in dfs['SEAWATER'].columns if MEAS_PAT.fullmatch(c)]

Convert U-238 units

The provider reports U-238 in parts per billion (ppb), the mass of uranium per mass of seawater. MARIS stores it in atoms per kg. ConvertU238CB converts the VALUE and UNC of U-238 rows and sets their UNIT to at_kg:

\[\text{atoms/kg} = C_{\text{ppb}} \times 10^{-9} \times 1000 \times \frac{N_A}{M_{238}}\]

(N_A = 6.02214076 {23} {-1}) is the Avogadro constant and (M_{238} = 238.05 ^{-1}) is the molar mass of U-238. The conversion factor is (2.530 {15} {-1},^{-1}). Rows for other nuclides are unchanged.

    "MARIS name of each id in `lut`, from the `name` lookup table"

What the pipeline drops

The pipeline leaves data out in four places: raw columns that the adapters don’t select, ETH values that VERA’s replace, samples without a measurement, and columns that the encoder doesn’t write. Each subsection computes one of them from the Zenodo records. The row counts after each step show that no other step removes a row.

Raw columns not kept

is_kept says whether a raw column survives the adapter, under its own name or after _RENAMES, the laboratory prefix or the date assembly:

def is_kept(col):
    "Whether the adapters keep raw column `col` in `RAW_COLS`, renamed or not"
    if col in ('Year', 'Month', 'Day'): return True
    return any(c in RAW_COLS for c in [_RENAMES.get(col, col), f'ETH_{col}', f'VERA_{col}'])
test_eq([is_kept(c) for c in ['Bottle', 'Year', 'U236_at_l', 'Water_Mass_ctd']], [True, True, True, False])

Rows after each step

step_counts runs the pipeline one callback at a time and counts the rows of each cruise after each one:

def step_counts(dfs, cbs, by='Cruise'):
    "Rows of each `by` value in the SEAWATER group, after each callback in `cbs`"
    rows = {'Loaded': dfs['SEAWATER'][by].value_counts()}
    for i, cb in enumerate(cbs, 1):
        tfm = Transformer({k: v.copy() for k, v in dfs.items()}, cbs=cbs[:i])
        tfm()
        rows[f'{i}. {type(cb).__name__}'] = tfm.dfs['SEAWATER'][by].value_counts()
    return pd.DataFrame(rows).T[dfs['SEAWATER'][by].unique()]

Only the reshape changes the counts. Before it, a row is a sample. After it, a row is a measurement. No later step removes a row:
